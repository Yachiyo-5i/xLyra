# 发布、签名与安装

xLyra **没有插件市场**。你把 `.xlp` 文件交给管理员，由管理员上传并启用。

## 开发者：打包

```bash
xlyra-plugin pack --sign my-key.pem
```

得到 `dist/<id>-<version>.xlp`。每次发布前请提高 `manifest.json` 里的 `version`：同一个 id 同一个版本如果内容不同，会被拒绝。

## 签名

签名是可选的，但建议做。签名用 ed25519：

1. `xlyra-plugin keygen --out my-key.pem` 生成密钥，**只做一次**，私钥自己保管。
2. 把输出的 `public_key` 发给管理员（或放在你的发布页面上）。
3. 之后每次 `pack --sign my-key.pem`。

签名覆盖包里除 `signature.json` 以外的所有文件。包在签名之后被改动，`verify` 和上传都会失败。

xLyra **不签发开发者证书**，信任关系完全由管理员决定：只有管理员手动导入的公钥才算"受信"。

## 管理员：安装

在管理后台的 **设置 → 开发者** 页面操作。

### 1. 导入受信公钥（可选）

在"受信公钥"里添加开发者给你的公钥。添加后，由该密钥签名的包就是"受信"的。

### 2. 上传

上传 `.xlp`。服务端会做静态校验、加载并运行包内样本，失败会显示原因，且不能启用。通过后状态为已验证。

### 3. 启用


选择某个版本启用：

- **受信签名**：直接启用。
- **未签名或签名者不在受信列表里**：需要二次确认，操作会写进审计日志。
- 同一个插件同一时间只有一个版本处于启用状态。启用新版本会让旧版本自动变为停用。

### 4. 让它生效

启用只是让 xLyra 加载插件；插件真正用在哪里，取决于类型：

| 类型 | 做法 |
| --- | --- |
| `quota_probe` | 在插件的操作里"绑定站点"，该站点的额度刷新改用它。站点编辑页的"额度探测"下拉框不会出现第三方插件 |
| `protocol` | 分配一个标识（slug），对外路径是 `POST /v1/plugins/<slug>` |
| `model_list`、`credential_check`、`error_classifier` | 在插件的操作里选择站点，点"绑定"；点"解除绑定"可以回到默认行为 |
| `pricing_parse` | 选择站点，先"预览价格"，核对后勾选确认，再"绑定" |
| `site_detect`、`model_metadata` | 不需要绑定，启用即对所有站点生效 |

同一个站点同一种类型同一时间只能绑定一个插件，重新绑定会替换。插件被停用或卸载后，对应的绑定自动失效，站点回到默认行为。

### 5. 试跑

"试跑"会在服务端用包内样本重新跑一遍，返回是否通过和耗时。它不会向真实站点发请求。

## 升级、回滚与卸载

| 操作 | 做法 |
| --- | --- |
| 升级 | 上传新版本，启用新版本 |
| 回滚 | 重新启用旧版本 |
| 停用 | 停用当前启用的版本 |
| 卸载 | 只能删除未启用的版本；启用中的版本要先停用 |

启用新版本时，新版本会先在后台完成加载和样本自检，通过后才切换，正在处理的请求不受影响。新版本加载失败则不切换，当前版本继续运行。

## 自动停用

运行异常的插件会被自动停用，规则见[限制与安全](./limits-and-security.md#自动保护熔断)。停用后不会自动回滚，由管理员决定。

## 审计

上传、启用、停用、卸载、绑定、试跑、导入或移除公钥，都会记入管理员审计日志，包含操作者、插件 id、版本和包摘要。

## 内置插件

xLyra 自带的内置插件（`xlyra.` 开头）只读展示，无法停用或卸载，它们也是你编写插件时的最佳参考。
