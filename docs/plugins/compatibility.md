# 版本与兼容

## 三个版本号

| 字段 | 含义 | 当前值 |
| --- | --- | --- |
| `apiVersion` | 钩子契约的版本：导出哪些钩子、参数和返回值的结构 | `1` |
| `hostApi` | 宿主 API 的版本：`codec`、`crypto`、`jwt`、`utils`、`log` 等全局函数 | `1` |
| `xlyra` | 你的插件兼容的 xLyra 版本范围（`>=x.y.z`） | 自定 |

`xlyra-plugin --version` 会打印当前 CLI 支持的 `apiVersion` 和 `hostApi`。

## 兼容规则

- **`apiVersion`**
  - 新增**可选**字段或**可选**钩子，不会升版本。
  - 删除字段或改变含义，会升到 `2`。升级后 xLyra 会同时支持 `1` 和 `2` 至少两个 minor 版本，期间管理端会标记"将停止支持"。
  - 目前返回值里出现**不认识的字段会报错**（`js_shape_error`），所以不要往返回值里塞自定义字段。
- **`hostApi`**：只增不改。新增函数时版本号加 1，你按需要在清单里声明最低版本。
- **`xlyra`**：声明的版本范围高于当前 xLyra 时，包会被拒绝；低于范围不会有影响。

## 引擎升级

xLyra 升级 JS 引擎后，启动时会对所有已启用的插件重跑样本。失败的插件不会加载，状态标为 `broken` 并告警，这也是为什么**样本要写得尽量完整**：它们是你的插件在引擎升级后还能继续工作的唯一保证。

## SDK 版本

npm 包 `@yachiyo-5i/xlyra-plugin-sdk` 与 `xlyra-plugin init` 写出的 `types/xlyra.d.ts` 内容相同，都是从服务端的契约结构生成的。

- 契约有变化时会同时更新两者。
- 在 `apiVersion 1` 冻结之前，SDK 的 `0.x` 版本可能有不兼容的调整。
